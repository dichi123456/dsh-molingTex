# dsh-plugin-moling-latex

**墨灵 LaTeX 的 DSH 插件**：在 DSH 右侧栏打开墨灵TeX 工作台 —— 目录树 · 编辑 · **LaTeX 自动补全** · 编译 · 日志 · PDF 预览 · **投屏讲解** · SyncTeX 双向定位 · **21 个内置模板**；另带 5 个 Agent 工具，让模型直接编译论文、读报错、定位源码行。

## 安装

### DSH 界面安装

设置 → 插件 → 右上「添加插件」，输入框填：

```
github:dichi123456/dsh-molingTex
```

输入框支持 **包名 / GitHub 仓库地址 / 本地目录路径** 三种；GitHub 源装的是 `main` 最新提交。

### 指定版本（Release 安装包）

```
plugin_manager install_bundle  https://github.com/dichi123456/dsh-molingTex/releases/download/v1.1.0/dsh-plugin-moling-latex-1.1.0.tgz
```

### 本地目录

```
plugin_manager install_bundle  <本仓库本地路径>
```

- 装完**重开 DSH**（宿主半侧要加载）；
- 需要本机 TeX 发行版（TeX Live / MiKTeX）；PDF 预览与双向定位用 TeX 自带的 poppler `pdftoppm` 与 `synctex`；
- 已装同版本会返回 `already-installed`：先 `remove_bundle` 再 `install_bundle`；
- 发布页：<https://github.com/dichi123456/dsh-molingTex/releases>

## 能做什么

**启动页**：标题区左侧带**墨灵 logo**（内联 SVG，跟桌面版同款：深蓝圆角方块 + 蓝紫渐变描边 + 白色 M 折线），右边是大标题与副标题；下面先看「最近」—— 工作区与文件分两组、各最多 5 条，点一个才进工作台；不自动打开任何项目。

**模板库**：启动页「模板」区**只放一个入口**（`浏览模板库`），点开是**二级弹窗** —— 左边分类导航（全部模板 / 中文论文 / 英文论文 / 简历 / 幻灯片 / 报告），右边搜索框（名称/描述/引擎都参与匹配）+ 卡片网格，共 21 个内置模板（中文/英文论文、IEEE、Elsevier、Wiley、国赛论文、简历、Beamer 幻灯片、实验报告）。新建空白文档走启动页「启动」区的 `新建文档`（Ctrl+N）。

点一张卡进入**第二步「新建文件」**：显示选中的模板与它的引擎/文件数，`选择文件夹…` 调系统目录选择器**让你自己挑存放位置**（会先把该目录登记进白名单，再允许落地），选好点 `创建` 才真正写盘。`返回` 回列表，`Esc` 逐级退出，点遮罩关闭。

弹窗**尺寸固定**（`min(620px, 88%)` 高），切分类、换搜索词、进出第二步都不会变大变小；模板多的时候只有卡片网格内部滚动，左边的分类导航和底部的「新建中文文档」入口始终在位。

- 主文件统一叫 `main.tex`；`.cls` / `.sty` / `.bib` / `.bst` 与图片按原始相对路径逐字节写出（国赛模板的 `figures/`、Elsevier 的 `figs/` 都在）；
- 目标目录里已经有 `main.tex` 时**改落到 `<模板id>[-n]/` 子目录**，绝不覆盖已有项目；
- 编译引擎跟着模板走（中文/幻灯片/简历 → `xelatex`，英文期刊/会议 → `pdflatex`），省得手点；
- 模板素材由宿主半侧从 `lib/templates/` 读盘下发，不进浏览器包（否则首屏要多背 1.1 MB）；清单端点只回元数据。
- 模板与桌面版墨灵TeX 同源，改模板后在本仓库跑 `node tools/sync-templates.mjs` 重新同步。

**工作台**

- 左侧 **CodeMirror 6** 编辑器：LaTeX 语法高亮（One Dark 配色）、行号（窄列，省地方）、软换行、多标签、**代码折叠**（`\begin{...}` … `\end{...}` 配对成块，点行号左侧箭头折起）；`F5` 编译、`Ctrl+S` 保存、`Ctrl+F` 查找、`Ctrl+Shift+F` 全项目搜索、`Ctrl+H` 替换、`F3` / `Shift+F3` 上下一个；
- **全项目搜索**（`Ctrl+Shift+F`，或编辑区右上角毛玻璃块第三颗图标）：宿主扫整个项目（跳过 `.aux/.log/.pdf` 等编译产物），结果按文件分组、带行号与命中上下文，点一条**直接打开那个文件并选中命中处**；上限 2000 条，查询串限 200 字；
- **查找 / 替换**（照搬桌面版墨灵TeX 的两行面板）：编辑区右上角毛玻璃悬浮块里两颗图标 —— **注释** 与 **放大镜**；放大镜点开查找面板（`Ctrl+F` / `Ctrl+H` 同效），面板内有查找框、`i / n` 计数、`Aa` 区分大小写、`.*` 正则、↑↓ 上下一个、`×` 关闭，第二行是替换框 + `替换` / `全部`；正则模式支持 `$1`–`$9` 与 `$&`。**所有命中涂琥珀色、当前命中涂红色**，选中相同词也会自动高亮；关掉面板高亮即清；
- **注释按钮**：选中若干行点一下，行首加 `%`；选中的行**全都有 `%`** 时反向取消（连着一个空格一起删掉）；空行跳过，缩进保留；
- **章节分割线**：`\part` / `\chapter` / `\section` / `\subsection` / `\subsubsection` / `\paragraph` 这些标题行**上沿自动画一条细横线**（首行除外，注释行不算），长文档滚动时一眼看得出章节边界；回退编辑器（内核加载失败时）同样有这条线；
- **章节底色带**：按**最浅一级**章节命令把全文切成若干段（有 `\chapter` 就按章、否则按 `\section`、再否则按 `\part`），相邻段**四档底色循环**（蓝 / 绿 / 琥珀 / 紫，透明度 0.04–0.05）—— 只够分开相邻章节，不压字、不抢眼，深浅主题下都不发灰；第一个章节之前的部分不着色。回退编辑器同款；
- **LaTeX 自动补全**（边打边弹，`Ctrl+Space` 手动唤出，`Tab` / `Enter` 选中，带占位符的项按 `Tab` 逐个跳字段）：
  - `\begin{` / `\end{` → 50 个常用环境；`\begin{figure` 会顺手补 `\end{figure}` 并把光标放在中间；
  - `\` 开头 → 100+ 常用命令（`\section` / `\textbf` / `\frac` / `\includegraphics` …），带参数的项直接是完整模板；
  - `\ref{` `\eqref{` … → **当前文档里的 `\label{...}`**；`\cite{` … → 当前文档里的 `\bibitem{...}` **加上项目里 `.bib` 文件中的条目**（逗号多引用只补最后一段）；
  - `\usepackage{` / `\documentclass{` → 常用宏包与文档类（`ctexart` / `IEEEtran` / `cas-dc` …）；
  - 词表在浏览器侧（`lib/client.js`），补全弹窗配色跟随主题，不额外写死颜色；
- **进入项目文件夹自动打开主 tex**：优先「你上次在这个项目里打开过的 .tex」，其次 `main.tex`，再次唯一/根目录唯一的 .tex，最后取体积最大的那个（没有 .tex 才什么都不开）；**切到另一个项目文件夹时，上一个项目打开的 tex 标签、PDF 预览与编译日志会一并关掉**（同一个项目重进不受影响）；
- **外部改动自动同步**：大模型（或任何编辑器）在磁盘上改了正在看的 tex，稳定一轮（约 2 秒）后自动进编辑区，**被改的行铺一层浅绿**、几秒后淡出，滚动位置不跳；标签里有未保存改动时只提醒、绝不覆盖。**自己保存 / 自己编译造成的 mtime 变化不会被当成外部改动**（先比内容指纹，一致就只盖版本戳、绝不重写编辑区），所以打字时光标不会被拽走；
- **每个对话各看各的项目**：面板状态按会话隔离 —— A 会话进了项目 A，切到 B 会话进项目 B，A 那边仍是项目 A，互不影响；切回来原样恢复（打开的标签、PDF、编译日志、文件树都在）。引擎/分栏宽度/自动保存这类**机器偏好**则共享；
- 顶栏：`首页`、工作区切换、`文件树 | 文件大纲`、`换行 | 保存 | 新建 | 自编`、连接状态胶囊、分体编译按钮（左键即编译，小三角切 完整 / 单趟 / 无图 / 从头）；**`保存` 是分体按钮**：左键立刻存（`Ctrl+S` 同效），小三角切 **手动保存 / 自动保存**（自动 = 停手 1.2 秒存一次）；**`自编` = 自动编译开关**：开着时保存或大模型改完文件后自动编一次（**静默 1.8 秒**才开编、编译中只记「待编」不排队、两次至少隔 3 秒，打字不会中途抽搐）；
- `文件树`：浮层文件树（**连编译辅助文件 `.aux/.toc/.out/.bbl/.log` 等也列出来**，可直接点开看），右边框可拖，**宽度随内容自适应**；进项目时抽屉不自动展开，要看再点；`文件大纲`：章节列表点一条跳一行；
- 底部状态栏：编译结果居中显示（成功绿 / 失败红），最右切换 `日志` / `PDF`。

**PDF 预览**：逐页图片，轻量不卡；栅格化固定 **96dpi**（≈屏幕 1:1，不再给用户选档位），`Ctrl+滚轮` 以鼠标为锚点缩放（0.5×–3×），`适应` 一键整页贴合当前窗口，顶栏 `第 x / N 页` 显示当前滚到第几页、点一下输入页码回车即可跳页（Esc 取消）；**页面直接紧贴分割线、不留黑边**（无内边距、无底色、无投影），页与页之间只留 8px；**页面比例按每一页自己的真实尺寸算**（A4 / beamer 4:3 / 16:9 都不会被拉变形，宿主用 `pdfinfo` 逐页读尺寸）；**单击页面跳回源码行**。面板内滚动条统一收成 8px 细圆角条，tex / pdf 交界处不再是一条粗灰边。**编译期间预览不动**：中间趟（第一趟 / bibtex / 补趟）的产物一概不上屏，只换最后那一份；拿不到图时保留旧图静默等，不报「PDF 不存在」、不退回内置阅读器、不抢你正在看的日志页。

**投屏讲解（PDF 放映 + 演讲者视图）**（v1.1.0 起）：PDF 区顶栏 `投屏` 一键开讲 —— 观众屏只显示**当前页**（**在系统默认浏览器里另开一个独立窗口**，拖到第二块屏 / 投影仪，**在那一页点一下画面就进全屏**，或按 `F11`），**本屏的墨灵面板那块**照 PowerPoint 的演讲者视图排（讲稿层只盖面板区，**左边对话照常可见**；缩放窗口、拖分栏、切全屏都会自动重算边界；配色跟 DSH 主题走 —— 亮色/暗色主题下都是同一套 `--dsw-alias-*` token，不是自己一套深蓝）：左边一整块是当前页（图下方居中一条「‹ 第 N 张幻灯片，共 M 张 ›」翻页条），右边一列上下三段 —— 上「下一张幻灯片」缩略图、中讲稿备注、**右下角计时**（从开放映起算，点数字暂停 / 继续、点 `↺` 归零，答辩掐时间用）；**最底下那条（左翻页条 / 右计时）定高一样，所以当前页底边、讲稿框底边、计时框底边是齐平的**；每页就是一张幻灯片（PDF 没有分步动画，所以不需要「下一步」）。旁挂 `.notes.md` 讲稿（见下）。

- **键位**（主窗和观众窗都认；输入框里打字不会被抢）：`→` `Space` `Enter` `PageDown` 下一页，`←` `PageUp` `Backspace` 上一页，`Shift+←/→` 前后 10 页，`Home` / `End` 首末页，**打数字再回车**跳页（1.5 秒内不打第二个数字就作废），`B` 黑屏、`W` 白屏（**只盖观众屏，自己这份照常看讲稿**），`N` 观众屏角标页码（默认关），`O` 缩略图总览（点一张跳过去），`?` 键位帮助，`Esc` 直接退出放映。
- **讲稿**：跟 PDF 同目录、同基名的 `<PDF基名>.notes.md`（找不到再找 `.notes.txt`）。分页认 `## 3` 这类标题（也认 `### 第 3 页` / `Page 3` / `Slide 3`）或单独一行的 `---`；**没有分页标记的段落当「通用讲稿」，每页都显示**；完全没有分页标记时整篇就是通用讲稿。极简 markdown（标题 / 列表 / 粗体 / `代码` / 分隔线）够用，不引第三方渲染器。顶栏「讲稿」按钮：已有备注就打开它，没有就问要不要**生成骨架**（每页一节 `## N`）再打开。
- **清晰度**：投屏图默认 **288dpi**，顶栏可在 96 / 144 / 200 / 288 / 400 五档切换，切完整组图重新取（含观众窗）；这个偏好记在本机 localStorage，不跟会话走。**为什么要到 288**：一块 1920 宽的屏铺满一张 4:3 幻灯片要 ~460dpi，200 投上去字仍是虚的（实测）；代价是单页 PNG 大约 0.6MB / 一张 1.2 秒，所以默认取中间的 288，真嫌慢就往下调一档。
- **整本预热**：点 `投屏` 开放映后自动把 1..N 页按当前 DPI 全渲染一遍（3 路并发，34 页 / 288dpi 约 5–8 秒），顶栏会显示 `预热 12/34` 的进度条，跑完变成 `预热完成 34 页`；**点一下进度条可以重跑**。为什么要做：平时只预取 ±1 页，评委问「第 20 页那张图」时现场跑 pdftoppm（约 0.2–0.5 秒/页）就是一秒白屏，答辩里很难看。预热结果落在宿主磁盘缓存里（`%TEMP%\dsh-moling-pdf`），**DSH 重启也还在**，可以前一天晚上跑好。**缓存键 = PDF 绝对路径 + mtime + dpi**，所以`重编译一次`或`换一档清晰度`都会让预热作废，这两种情况会自动重跑（答辩前预热完就别再编译）；取消/退出会 `AbortController.abort()` 掐掉在飞的请求，不让宿主白烧 CPU 落一堆没人要的图。有页失败会红字报 `预热 N 页失败`，不谎报成功。
- **页面不会「只显示半页」**：栅格化改成**写临时文件再原子改名**，命中缓存前还要校验 PNG 尾部有 `IEND` —— 以前是 pdftoppm 直接往缓存名写，另一个并发请求（比如主窗讲稿层和观众窗同时要同一页）会读到写了一半的图，浏览器不报错、只画上半页、下半截留黑（这正是之前高 dpi 下「显示不全」的原因，96dpi 因为早就缓存好了反而不容易撞上）。观众页换页也改成**离屏载完再换图**，载失败自动重试一次，翻页不再闪白。
- **缓存不会无限长**：栅格化缓存的键里带 PDF 的 mtime，每编译一次整批作废、旧图一直留着 —— 实测攒到 2.3 万个 PNG / 1.29GB。现在超过 **320MB** 就按 mtime 从旧到新删到 200MB（每 5 分钟最多查一次总量），删的只是缓存，要用哪页重新渲染一次即可。
- **副屏**：观众窗是个普通浏览器窗口，位置/大小/全屏都交给系统和浏览器 —— 拖到第二块屏后**点一下画面即全屏**（没进全屏时页面底部会一直挂着一条「点一下画面即可全屏」的提示，B/W 黑屏白屏时不显示）；直接按 `F11` 也一样（浏览器会记住位置，下次开就在那儿）。关掉了点顶栏 `观众窗` 再叫一个出来。
- **为什么是系统浏览器而不是应用内新窗口**：桌面版主窗的地址是 `dsh-app://app`（自定义协议），宿主只放行 `http(s)` 链接去调用系统浏览器、其余一律拒掉；所以观众页开在宿主自己的本地 http 地址上（面板自动从 `__DSH_TRANSPORT__.streamBaseUrl` 取真实 origin）。万一还是没弹出来，状态栏会把观众页地址写出来 —— 复制到任意浏览器打开即可，放映照样同步。
- **两窗同步**走宿主中转（观众页在另一个浏览器进程里，`BroadcastChannel` 跨不过去）：主窗每次翻页 / 黑屏 / 换清晰度都把状态推给宿主，观众页 220ms 轮询一次跟上；观众窗里按的键反过来排队回传主窗。**关掉观众窗不会中断**（讲稿层还在，点顶栏 `观众窗` 可重开）。
- **不打扰现有预览**：放映时右栏 PDF 跟着滚到当前页；退出放映就停在最后一页。**PDF 被重新编译 / 换成另一个 PDF / 切会话 / 关项目，放映会自动收摊**，不留僵尸窗口。

- 浏览器硬限制（四条，绕不过去）：① 观众窗的**全屏必须由那个窗口自己点一下**触发（浏览器安全策略，点按钮或点画面都算，但这一次手势躲不掉），主窗里按 `F` 管不到外部窗口；② 放映中弹系统弹窗 / 抢焦点可能把全屏踢掉，再点一次即可；③ 刷新 DSH 页面或切会话会断放映（这是刷新本身，观众页会显示「放映已结束」）；④ 讲稿层跟着面板卸载一起拆掉，不会残留在页面上。

**SyncTeX 双向定位**：编辑器右键「定位到 PDF 位置」→ 源码行跳到 PDF 对应页并画黄圈；PDF 上单击 → 跳回源码行（**文件树/提纲等浮层会自动收起，目标行闪一下绿**，不会"跳了却看不出来"）；结果显示在底部状态栏，失败也一定会说明原因。

**与对话框联动**

- **连接状态胶囊**：项目是否已在 DSH 工作区（绿 / 黄 / 灰），未连接时点一下直接加入；
- **发送选中内容**：编辑器右键「发送选中内容到对话框」，把选区以 **DSH 原生 `@` 引用 chip**（圆角方框，如 `Safety_MARL框架.tex:20`）送进当前会话输入框，不自动发送。chip 通过会话作用域的 `slash/input-insert-reference` 事件生成（不是伪造的纯文本）；造不出 chip 时自动退回一行纯文本引用，并在状态栏说明原因。

## Agent 工具

| 工具 | 作用 |
| --- | --- |
| `latex_compile` | 编译 `.tex`。`quick` 单趟 draft（**图片占位，看不到图**）；`once` 单趟完整排版（**图片照常插入**，不跑 bibtex、不补趟，交叉引用/目录可能沿用上一趟）；`full` 主编译 →（需要时）bibtex → 再编译 → 视 Rerun 提示补一趟；`clean` 先清辅助文件再走 full |
| `latex_status` | TeX Live / MiKTeX 探测：bin 目录、版本、六个引擎路径 |
| `latex_synctex` | SyncTeX 双向同步：源码行 → PDF 坐标；PDF 坐标 → 源码行 |
| `latex_clean` | 删除 `.aux/.log/.toc/.out/.bbl/.synctex.gz/...`（不碰 `.tex/.pdf/.bib`） |
| `latex_outline` | 章节标题与行号、`\input`/`\include` 依赖、`\label`/`\cite` 计数 |

引擎缺省 `auto`：`ctex`/中文 → `xelatex`；`IEEEtran`/`elsarticle`/`article` → `pdflatex`。

**编译提速**（v1.0.2 起）：xelatex 的中间趟一律 `-no-pdf`，只排版不写 PDF（`.xdv` 才 379 KB，而每趟重写十几 MB 的 PDF 才是慢的大头），最后一次统一跑 `xdvipdfmx`。实测同一份 28 页 beamer（22 张图、产物 13.7 MB）：`full` **24s → 约 9.5s**、`once` **约 6s**、`quick` **约 3.5s**。等价性核过：页数、`pdfimages` 图像对象数、逐页像素渲染全一致。

**编译结果判定**（v1.0.2 起）：`-file-line-error` 下警告与错误同格式，现在按消息内容区分 —— `Package/Class/LaTeX/Module/Font Warning`、`Overfull/Underfull \hbox`、`Missing character` 等一律算**警告**（不再让面板误报「编译失败」）；日志与成败**只取最后一趟**，头行标「（结果取最后一趟）」与「N 条错误 · M 条警告」；警告条目同样可点击跳转。

**PDF 后端偶发失败自动重试**（v1.0.2 起）：TeX Live 2024 的 `xdvipdfmx` 会随机抛 `pdf_link_obj(): passed invalid object.` + `No output PDF file written`（同一份 `.xdv` 连跑 6 次只成功 1 次，是上游缺陷）。只在「日志里没有 LaTeX 错误、失败点确实在 PDF 后端」时自动重跑 2 次；真错误绝不重跑。仍然失败时给出可读原因，而不是只说「编译失败」。

**插图净化：从根上消掉那个后端缺陷**（v1.0.3 起）：上面那个 `pdf_link_obj()` 不是随机故障，是**某几张插图**触发的 —— 真项目 25 张图里 6 张是 PDF 1.5 对象流（`/ObjStm` + `/Type /XRef`），只把这 6 张用 `pdftocairo -pdf` 重写（矢量保真，逐像素差异只在抗锯齿级别），同一份 `.xdv` 连跑 15 次从 **8/15 变成 15/15**。现在每次开编前自动扫主文件与 `\input`/`\include` 里的 `\includegraphics`，把含对象流的 PDF 图重写到临时缓存目录（按「路径 + mtime + 体积」缓存，改图才重算），再把影子目录塞进 `TEXINPUTS` **最前面** —— 必须赶在排版之前，因为 `.xdv` 里记的是排版时解析到的图路径（只在 `xdvipdfmx` 阶段换图无效，实测等于没换）。没有需要净化的图时这一步完全不介入，编译路径与以前一模一样；`pdftocairo` 缺失或重写失败也只是安静退回原图。真项目实测：首次多 4.6 秒（6 张图），之后命中缓存 0 开销，连跑 4 次全部一次过、零重跑。

**辅助文件脏标记**（v1.0.3 起）：编译中途被打断（`Emergency stop` / `fatal` / 后端没写出 PDF / 用户取消）会留下半截 `.aux`、`.nav`，下一趟读回去就是「第一次失败、再点一次才成功」。现在失败时只把**这一趟确实写过**的 `.aux/.nav/.out/.toc/.snm/.bcf` 记成脏（存临时目录，不往项目里塞文件），下次开编前只清这几个，并在结果里明说「已因上次中断清理辅助文件」—— **不是每次都 clean**，平时照常复用交叉引用。


**两套入口不会打架**（v1.0.0 起）：

- **同一份文档的编译排队**：面板按钮、面板「自编」、Agent 的 `latex_compile` 都走同一个队列（按「目录 + 主文件名」串行），不会再有两个进程同时写同一批 `.aux` / `.log` / `.pdf`；
- **工具沿用面板档位**：Agent 调 `latex_compile` 时如果**没有显式传** `mode` / `engine`，而这份文件正是面板上次编译的那一份，就沿用面板的档位（比如面板选了「无图 / xelatex」，工具也用无图 / xelatex），不会出现一边 pdflatex 一边 xelatex 把 `.aux` 写坏、只能清辅助文件才能恢复的情况。要强制另一套，显式传 `mode` / `engine` 即可。

## 排错

| 现象 | 处理 |
| --- | --- |
| 右侧栏没有「墨灵 LaTeX」入口 | 插件没挂载：`plugin_manager list_bundles` 看有没有 `dsh-plugin-moling-latex`，没有就重装 |
| 面板状态灯是红的 | 数据通道异常：确认 `GET /moling/api/ping` 能返回 `{"ok":true,...}`，否则是宿主半侧没装载 |
| 打开文件夹后列表是空的 | 列表区会写原因：`不在允许范围内` → 用启动页「打开文件夹…」重开一次；`另有 N 个其它文件` → 该目录确实没有支持的类型 |
| 编译报「找不到引擎」 | 让 Agent 跑 `latex_status`，或在插件配置里指 `texlivePath` |
| 编译失败但日志里没错误 | 开编前会自动净化含对象流的 PDF 插图（真项目实测把后端失败率从 1/3 降到 0），仍失败会自动重跑 PDF 后端 2 次；还不行会给出上游原因（`pdf_link_obj(): passed invalid object.` 是 TeX Live 2024 的已知缺陷，再点一次编译通常就过） |
| PDF 预览空白 | 先看底部状态条：写「降分辨率预览不可用」= 取图失败（已退回内置阅读器）；两样都空就用 `latex_compile` 重新编译一次 |
| 改了代码后面板没变化 | 只改 `lib/client.js` 刷新页面即可；改 `lib/server.js` / `lib/index.js` 要**重开 DSH** |
